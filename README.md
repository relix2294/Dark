# Dark — Lablabu + Sor Box

Платформа быстрой доставки для Душанбе: **Lablabu** (дарк-стор, обещание 15 минут) и **Sor Box** (кухня, 45 минут).
Один бэкенд, два бренда, много точек. Бренд и точка — поля данных, не отдельные инсталляции.

- Бизнес-ТЗ и техническая спецификация: [docs/spec/TECH_SPEC.md](docs/spec/TECH_SPEC.md)
- Архитектура и выбор стека: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), решения — [docs/adr](docs/adr)

## Стек

| Слой | Выбор | Почему |
| --- | --- | --- |
| Язык | TypeScript везде (Node 22) | Один язык на сервере и во всех клиентах; типы контракта общие |
| API | Fastify 5 + zod | Схема запроса = валидация = OpenAPI; быстрый, без магии |
| БД | PostgreSQL 16 + Drizzle ORM | Транзакции, CHECK-инварианты, миграции SQL в репозитории |
| Очереди | pg-boss | Очередь прямо в Postgres: outbox, повторы capture, тик диспетчера. Без Redis |
| Realtime | SSE (клиент), WebSocket (экраны персонала) | По ТЗ §1 |
| Фронты | React 19 + Vite + PWA | Витрина, админка/пульт, кухня, терминал сборщика |
| Курьер | Expo (React Native) | Фоновая геопозиция и пуши — PWA этого не умеет |
| Монорепо | pnpm workspaces + Turborepo | Общий пакет контрактов, одна команда проверки |

## Структура

```
apps/api            модульный монолит (Fastify): core-api, payments, wms, kds, dispatch, backoffice, notify
apps/storefront     витрина клиента внутри DC Next (React PWA)        /store
apps/backoffice     админка + пульт старшего смены (React)            /office
apps/kds            экран кухни (React, планшет)                      /kds
apps/picker         терминал сборщика (React PWA, Android-терминал)   /picker
apps/courier        приложение курьера (React PWA, затем Expo)        /courier
packages/contracts  zod-схемы API: единственный источник типов для сервера и клиентов
packages/ui         общее для клиентов: API-клиент, вход по PIN, компоненты, хук сканера
deploy/             docker-compose + Caddy для VPS
docs/               ТЗ, архитектура, ADR
scripts/            проверка границ модулей
```

## Запуск локально

Нужны Node 22, pnpm 10 и PostgreSQL 16 (локально или в Docker).

```bash
pnpm install
cp .env.example .env            # поправьте DATABASE_URL и JWT_SECRET
pnpm --filter @dark/contracts build
pnpm db:migrate                 # применить миграции
pnpm db:seed                    # демо-точка в Душанбе, персонал +99290000000{1..7}, PIN 1234
pnpm api                        # http://localhost:3000, Swagger — /docs
pnpm dev                        # все фронты: /store :5171, /office :5172, /kds :5173, /picker :5174, /courier :5175
```

Демо-персонал после `pnpm db:seed`: `+99290000000{1..7}` (сборщик, повар, курьер, старший смены, управляющий, финансист, админ), PIN `1234`.
Витрина в разработке принимает токен DC Next вида `dc:<любой id>`.

Сквозной сценарий в браузере (витрина → сборщик → диспетчер → курьер → пульт → кухня): `pnpm e2e` при запущенных API и `pnpm dev`.

Проверка всего проекта одной командой (то же, что в CI):

```bash
pnpm check                      # границы модулей, типы, тесты
```

Тесты сценариев приёмки ходят в настоящий Postgres: `TEST_DATABASE_URL=postgres://dark:dark@127.0.0.1:5432/dark_test`.

## Что уже работает

Бэкенд покрывает все разделы ТЗ; 119 тестов, большая часть — сценарии приёмки против настоящего Postgres.

- **Контракт** (`packages/contracts`): бренды, статусы, коды ошибок, схемы всех запросов и ответов. OpenAPI — `/docs`.
- **Данные**: все таблицы ТЗ §2 плюс outbox, идемпотентность, параметры, журнал, pick_task, kds_item, stop_list. Инварианты — CHECK и триггеры в БД.
- **Заказ** (`/cart`, `/orders`): корзина, PRICE_CHANGED, резерв FEFO с блокировкой до холда, холд через адаптер, отказ/таймаут банка, отмена клиентом, SSE-статус с курьером.
- **Склад** (`/wms/*`): задание сборщику в порядке обхода ячеек, скан ячейка→товар→количество, весовой товар, нет товара → call/auto/remove, ярлык пакета; приёмка, подсказка и проверка ячейки, списание (запрос/утверждение), инвентаризация.
- **Кухня** (`/kds/*`): раскладка блюд по станциям «всё готово одновременно», очередь с цветами, упаковка → ready, списание ингредиентов по рецептуре, стоп-лист, который убирает блюда с витрины.
- **Курьеры** (`/courier/*`): смена, геопозиция пакетами по времени события, задание, скан ярлыков → on_the_way, доставка с геозоной, «клиент не вышел», автоматический returning → free у точки.
- **Диспетчер** (воркер каждые 15 с): срочные SOR → LAB по очереди → остальные SOR с резервом под LAB; истечение предложений; тревоги NO_COURIER; снимок входа в каждом задании.
- **Платежи**: capture при доставке с повторами 1/5/15 мин и далее ежечасно, release при отмене, частичное списание при неявке и отмене SOR, refund с лимитом по роли, сверка зависших `*_pending`.
- **Пульт старшего смены** (`/console/*`): заказы и курьеры точки, ручное назначение с причиной, отмена, приём возврата, возврат денег. Всё в журнале действий.
- **Параметры** по точке (ТЗ §12), вход персонала по PIN, матрица прав ТЗ §9, события outbox, pg-boss.
- **Админка** (`/admin/*` и экраны в `/office`): точки, категории, товары, цены с историей, блюда, зоны, промо, персонал и роли,
  ячейки, поставки, остатки, корректировка, график курьеров по прогнозу, отчёты (сводка и «Деньги»).
- **Realtime**: WebSocket для экранов персонала поверх outbox и Postgres `LISTEN/NOTIFY` (работает при нескольких инстансах).
- **Модификаторы блюд** Sor Box: группы с обязательностью и лимитом, доплата считается сервером, кухня видит состав.
- **Склад по ТЗ §7 целиком**: внутренние штрихкоды EAN-13 для товаров без кода и печать этикеток, список на уценку
  и списание по срокам, инвентаризация от ежедневного плана до применения расхождений управляющим, замена по звонку с таймером 60 с.
- **Правила ТЗ §8 и §11**: параметры точки действуют во всех сервисах, отсечка заказов перед закрытием, обещание Sor Box
  до оплаты по загрузке кухни, не больше двух новичков на адрес, доставку вне геозоны подтверждает старший смены.
- **Импорт каталога из CSV** (выгрузка Excel/1С): проверка без записи с ошибками по строкам, затем применение одной транзакцией;
  пример файла — `scripts/fixtures/catalog-example.csv`.
- **Карты** (Leaflet, без ключей): адрес доставки в витрине с проверкой зоны, точка, курьеры и заказы на пульте, зона рисуется кликами.
- **Без связи**: терминал сборщика принимает сканы офлайн до 30 минут и отправляет очередь при восстановлении.
- **Мониторинг**: `/metrics` для Prometheus и правила тревог по таблице ТЗ §10 (`deploy/alerts.yml`).
  Деньги под присмотром: снятие холдов у отменённых заказов, тревога об истечении холда, ночная сверка с банком.
- **Клиенты** (React + Vite, PWA, общий `@dark/ui`): витрина, терминал сборщика со сканером, экран кухни, пульт и админка, приложение курьера.
  Сквозной сценарий проверен в браузере скриптом `scripts/e2e.mjs`.

## Деплой

VPS с Docker: `deploy/docker-compose.yml` поднимает Postgres, миграции, API и Caddy с автоматическим TLS.
Фронты собираются командой `pnpm build:web` в `deploy/www` и отдаются Caddy по путям `/store`, `/office`, `/kds`, `/picker`, `/courier`.
CI (GitHub Actions) на каждый пуш в `main` прогоняет проверки и публикует образ `ghcr.io/relix2294/dark-api`.
