# ADR-009. Звонки курьер ↔ клиент через подменные номера

**Контекст.** ТЗ §9: «доставка и звонок через скрытый номер». Решение заказчика: звонок — из приложения, через подменный
номер, как в такси: ни курьер, ни клиент не видят настоящий номер другой стороны. Провайдер телефонии ещё выбирается.

**Решение.** Модуль `calls` с интерфейсом `CallProxy` (`bind / unbind`) и заглушкой `StubCallProxy` — тот же приём, что для кошелька (ADR-007).
- Связка номеров (`call_session`) — одна активная на заказ, создаётся при заборе пакета, чтобы номер был у курьера заранее и
  набирался без связи с нашим сервером. При смене курьера старая связка снимается.
- «Позвонить» (`POST /courier/orders/:id/call`, `POST /orders/:id/call-courier`) возвращает номер для набора; телефон звонит
  обычным звонком (`tel:`), соединяет провайдер. Настоящий номер клиента приходит из DC при входе и наружу не отдаётся.
- Каждое нажатие пишется в `call_attempt` временем события. «Клиент не вышел» сервер принимает только после 2 звонков курьера
  и `NO_SHOW_WAIT` от первого (ТЗ §11) — правило проверяет сервер, а не кнопка.
- Связки закрываются воркером: истёкшие (4 ч) и через 30 минут после доставки или закрытия заказа.
- Сбой провайдера — `CALL_UNAVAILABLE` (503); подмены настоящим номером нет.

**Последствия.** Подключение провайдера — один адаптер (вебхуки о длительности и ответе звонка лягут в `call_attempt`).
Если провайдер даёт звонок прямо из браузера (WebRTC), это ещё один метод того же адаптера, правила не меняются.
