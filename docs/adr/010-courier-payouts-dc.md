# ADR-010. Оплата курьерам — только безналично, выплаты через DC

**Контекст.** Открытый вопрос ТЗ §12 «модель оплаты курьеров». Решение заказчика: все деньги — только безналичные и только
через DC; курьер наличных в руки не берёт. Lablabu и Sor Box живут как мини-приложения внутри экосистемы DC.

**Решение.**
- Начисление за смену по тарифу точки — параметры `COURIER_PAY_PER_DELIVERY_DIRAMS`, `COURIER_PAY_PER_KM_DIRAMS`,
  `COURIER_PAY_PER_HOUR_DIRAMS` (стартовые 5 с, 1 с, 0 с; меняются в админке без выкладки). «Клиент не вышел» оплачивается как
  доставка — поездка сделана. Пробег — по GPS-треку без неточных точек и скачков.
- При закрытии смены создаётся одна выплата за смену (`courier_payout`, уникальный `shift_id`); доплата управляющего или
  финансиста — отдельная выплата с причиной и записью в журнал. Удержаний нет: с кошелька не списываем.
- Отправку делает воркер через `WalletAdapter.payout` с ключом идемпотентности = id выплаты: повтор не платит дважды.
  Нет кошелька DC у курьера — `no_wallet`; банк не ответил — повторы 1/5/15/60 минут; отказ — `failed`; оба случая — событие
  `payout.failed` (тревога на пульт и финансисту) и ручной «Повторить» тем же ключом.
- Кошелёк DC — в карточке сотрудника, один кошелёк — один сотрудник.

**Последствия.** Ставки и правила начисления (бонусы за часы пик, гарантия за смену) — параметры и функция `shiftPay`, без
изменений в схеме. Реальный вызов выплаты — метод адаптера DC, когда банк даст API.
