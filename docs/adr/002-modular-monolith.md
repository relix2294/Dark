# ADR-002. Модульный монолит с проверяемыми границами

**Контекст.** ТЗ §1: модули общаются через события и внутренние интерфейсы, не через чужие таблицы; микросервисы на 4 точки избыточны.
Деньги и остатки меняются только в транзакции — распределённые транзакции между сервисами усложнили бы это многократно.

**Решение.** Один процесс, папка `modules/<name>` на модуль, публичный интерфейс — `index.ts`. Границы проверяет
`scripts/check-boundaries.mjs` (ошибка CI при импорте внутренностей чужого модуля или импорте модулей из `shared`).
Таблицы имеют владельца (`OWNERSHIP`); запись в чужую таблицу — нарушение на ревью.

**Последствия.** Дешёвые транзакции между модулями, один деплой. Если модуль (например `dispatch`) потребует отдельного масштабирования,
его можно вынести: он уже общается с остальными через интерфейс и события outbox.
