# ADR-008. Realtime через outbox и Postgres LISTEN/NOTIFY

**Контекст.** Пульт, кухня, терминал и курьер должны видеть изменения сразу (ТЗ §1). Событие рождается в транзакции на любом
инстансе API, а сокет клиента может быть открыт на другом. Redis в стеке нет (ADR-003).

**Решение.** Relay outbox для каждого события определяет точку (по агрегату) и делает `pg_notify('dark_events', …)`.
Каждый инстанс API держит одно соединение `LISTEN dark_events` и рассылает сигнал сокетам этой точки. Сообщение — только
«что изменилось», без данных: клиент перечитывает через REST, где права проверяются как обычно.

**Альтернативы.** Рассылка из памяти процесса — ломается при втором инстансе. Redis pub/sub — лишний сервис.
Данные в сообщении — пришлось бы дублировать проверку прав в канале событий.

**Последствия.** Задержка — интервал relay (до 2 с). Лимит NOTIFY 8000 байт не мешает: сообщение — несколько полей.
Если событий станет очень много, канал переносится на Redis за тем же интерфейсом модуля `realtime`.
