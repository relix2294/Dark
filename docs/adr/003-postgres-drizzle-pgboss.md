# ADR-003. PostgreSQL + Drizzle ORM, очередь pg-boss вместо Redis

**Контекст.** Нужны транзакции, CHECK-инварианты, блокировки строк для резерва (§11), миграции в репозитории, фоновые задачи
(outbox, повторы capture, тик диспетчера, ночная сверка).

**Решение.** PostgreSQL 16. Drizzle ORM: схема в TypeScript, `drizzle-kit generate` создаёт SQL-миграции, SQL виден и правится руками
(инварианты, триггеры — `0001_invariants.sql`). Очередь задач — pg-boss (таблицы в схеме `pgboss` той же БД): cron, повторы, singleton-задания.

**Альтернативы.** Prisma — миграции менее прозрачны, тяжёлый клиент; BullMQ + Redis — ещё один сервис в проде и ещё одна точка отказа.

**Последствия.** Один stateful-компонент (Postgres) — проще бэкапы и деплой на одном VPS. Если нагрузка на очередь вырастет на порядки,
pg-boss заменяется на Redis-очередь за тем же интерфейсом в `workers.ts`.
